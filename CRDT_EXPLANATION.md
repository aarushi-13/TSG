# CRDT explanation

## Current Yjs model

Each document editor acquires its own Y.Doc through `YjsIndexedDBStore`. The y-indexeddb provider restores the document before editor initialization. TipTap Collaboration binds ProseMirror to the `default` Y.XmlFragment; StarterKit undo is disabled and the collaboration extension provides Yjs-aware undo/redo. Existing IndexedDB TipTap JSON is converted into the Y.XmlFragment exactly once when the Yjs document is empty. A marker prevents later reopen from re-seeding stale JSON. Yjs updates persist locally, and a debounced JSON projection keeps dashboard snippets current.

Yjs updates are designed to be commutative, associative, and idempotent. Unit tests create independent Y.Doc replicas, make concurrent edits through real TipTap Collaboration editors, exchange updates in different orders, replay duplicates, and compare normalized resulting document contents. Phase 5 adds y-webrtc, which sends Yjs sync messages over WebRTC data channels; Playwright tests exercise independent Chromium contexts through actual local signaling and WebRTC rather than directly passing Yjs updates in memory. Each document has an independent room named by its document ID.

Yjs resolves concurrent operations deterministically; it does not inherently identify a semantic “same paragraph” conflict. Phase 6 adds an application layer: each local block update appends author/time/causal metadata and before/after ProseMirror snapshots into a shared Y.Array. Intents are grouped by stable Yjs block identity and concurrent editing episode; multiple character operations in one paragraph create one conflict entry. Separate conflicting blocks create separate entries. The conflict UI lets a user choose either version, write custom text, or defer; the decision and rich resolved block synchronize through the same Y.Doc. A saved resolution is applied by every connected editor.

This does not make semantic conflict detection complete. Candidate block JSON preserves supported node types, attrs, marks, links and nested content; resolution replaces only the affected block, so surrounding formatting and document structure are retained. Custom text keeps the selected base block and carries marks through unchanged text and the replacement range. The grouping layer identifies concurrent changes to one block, but it does not infer user intent or perform general semantic merging. Shared intents/records are persisted by y-indexeddb and included in peer synchronization. Phase 4's separate append-only local archive still keeps checkpoints and raw generated update bytes because y-indexeddb may compact its restore log.

## Status

Yjs and y-indexeddb are integrated with TipTap Collaboration in `src/editor/DocumentEditor.tsx`, with the store lifecycle in `src/persistence/yjsStore.ts` and seed/projection helpers in `src/crdt/document.ts`. The peer lifecycle and Awareness integration live in `src/networking/peerProvider.ts`; conflict intents/classification live in `src/conflicts/conflictManager.ts`; the signaling-only Node service is in `signaling/server.ts`. Independent-browser tests verify the local signaling/WebRTC path and short offline recovery; they do not claim universal cross-network connectivity or long-term endurance.
